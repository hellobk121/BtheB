## 1. 목적

| 항목 | 내용 |
|---|---|
| 한 줄 | 책을 읽은 사람에게 철학자 페르소나가 **정답 대신 질문**으로 사고를 이끄는 웹 서비스 |
| 이름 | Beyond the Book → BtheB |
| 포트폴리오 목적 | 이력서 B(AI 솔루션 개발자)의 코드·배포 증거. RAG, 에이전트, 모델 서빙, 배포, 경량 LLMOps |

| 진행 원칙 | **안정 + 애자일**: 끝까지 동작하는 얇은 조각을 만들고, 조각마다 테스트·README 갱신 후 다음으로 |
| 기한 | 10/30 이력서 제출과 분리. 급하지 않게, 늘어지지 않게 |

## 2. 합의된 결정

| 결정 | 선택 | 이유 |
|---|---|---|
| 클라이언트 | 웹 (모바일 우선, QR 진입) | 설치 없이 열림, URL이 곧 증거 |
| 프론트 | **React** (Vite) | 책 목록·로그인·성장 대시보드로 확장 예정이라 처음부터 사용 |
| 스트리밍 | **MVP는 없음(일반 요청-응답)**, 답이 느리면 별도 조각으로 SSE 추가 | headless와 평가 실험에는 전체 응답이 편함, 추가 시 `/chat`과 화면만 변경 |
| 백엔드 | FastAPI (Python) | LLM·RAG 생태계, JD 요구 스택 |
| 벡터 DB | Chroma (로컬 파일) | 설치 단순, 로컬 개발에 충분 |
| LLM 호출 | **어댑터 인터페이스** | 비용 때문에 개발은 headless, 공개는 API, 이후 소형 오픈모델 비교 |
| 개발용 LLM | Claude headless (`claude -p`) | 구독 한도 안에서 추가 비용 없음. **개발·본인 시연 전용** |
| 공개용 LLM | Claude API (저가 모델) + 요청 한도 | 구독을 타인 서비스에 쓰는 것은 약관 확인 전까지 하지 않음 |
| 페르소나 | **맹자** (니체는 예시였음) | 『맹자』는 대화체 원전이라 질문 유도 구조에 맞음 |
| 텍스트 | **1층 = 맹자 해설서 PDF(OCR), 2층 = 한문 원문 PDF. 로컬 전용, 저장소에는 자료를 커밋하지 않음** (`etc/`, `data/books/` ignore). 외부 공개는 권리자 허락 후 | 해설서(이혜경 2004)와 원문 전산본은 각각 권리가 있을 수 있음. 허락 구조가 B2B 모델과 일치 |
| 임베딩 | 다국어 모델(BGE-M3, multilingual-e5 후보), M1에서 한국어 질문 20개로 비교 후 확정. 한문 원문 지원 여부 확인 | 한국어 해설서와 한문 원문을 함께 다뤄야 함, 선택 근거를 포트폴리오에 남김 |
| 사용자 | MVP는 성인 독서모임 | 피드백 확보 쉽고 미성년 동의 문제 없음 |

## 3. 아키텍처

```
브라우저 (React)  --HTTP-->  FastAPI  --> RAG --> Chroma
                              |
                              +--> LLM 어댑터 --> claude_cli | claude_api | (later) local_lora
```

### 3-1. 파이프라인

```
[인덱싱: 책마다 1회]
책 텍스트 → 문단 청크 → 임베딩 → Chroma 저장 (메타데이터: book_id, 페이지/위치)

[질문마다]
질문 → 임베딩 → 상위 k개 청크 검색
     → 프롬프트 = 페르소나 지침 + 검색 청크 + 대화 기록 + "정답 직접 제시 금지, 질문으로 유도"
     → LLM → 답변 + 인용 위치 → 로그 저장 (평가용)
```

### 3-2. 컴포넌트 경계

| 단위 | 역할 | 의존 |
|---|---|---|
| `llm/` | `generate(messages) -> stream` 인터페이스와 구현체들 | 없음 |
| `rag/` | 청킹, 임베딩, 인덱싱, 검색 | Chroma |
| `persona/` | 철학자별 지침(YAML/MD), 프롬프트 조립 | 없음 |
| `api/` | `/health`, `/books`, `/chat` | llm, rag, persona |
| `frontend/` | 채팅 화면, 이후 책 목록·대시보드 | api |
| `eval/` | 평가셋, 지표 계산 | llm, rag |

각 단위는 내부를 몰라도 인터페이스만으로 쓸 수 있고, 따로 테스트한다.

## 5. 마일스톤

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **M0 인프라 (오늘)** | git 연결, README, 폴더 뼈대, `.env.example`, LLM 어댑터 인터페이스, `/health` | 로컬에서 서버가 뜨고 README의 실행 방법대로 재현됨, 첫 push |
| M1 자료 수집 + RAG 최소 | 해설서 샘플 20~30쪽 OCR(방식 2~3개 비교, 글자 오류율 측정), 원문 PDF 정리(편·장·절 코드), 인덱싱, 검색, 인용 포함 답변 (처음부터 구현, 스크립트로 시작) | 질문 10개에 인용 위치가 맞는 답이 옴 (수동 확인) |
| M2 채팅 UI | React 채팅 화면(일반 요청-응답) + 맹자 페르소나 | 휴대폰 브라우저에서 한 대화가 끝까지 됨 |
| M3 평가 | 답 누설률, 인용 정확도, 질문 품질 루브릭, 지연·비용 로그 | 프롬프트만 vs RAG 비교표가 README에 있음 |
| M4 모델 비교 | LoRA 페르소나 소형모델 + 서빙, API LLM과 비교 | 충실도·누설률·비용·지연 비교표 |
| M5 배포·확장 | API 백엔드 전환, 요청 한도, 공개 URL, 책 목록·로그인, 에이전트 도구화 | 외부 사용자 5~10명 테스트 |

**MVP = M1 + M2** (질의응답 1차 구현). 포함: 해설서 샘플 20~30쪽(OCR), 한문 원문 조회(장·절 코드), 맹자 페르소나 질문 유도, 근거 문단 인용, React 채팅 화면, 답 직접 제시 여부 수동 확인. 제외: 책 목록·로그인·대시보드, 미션·토론, LoRA·서빙, SSE, 에이전트, 배포, 정량 평가.

M0의 첫 push 외에 각 단계 끝에서 README의 "현재 상태 / 아직 안 한 것"을 갱신한다.

| 위험 | 대응 |

## 8. 열린 질문

1. **1층(결정)**: 이혜경, 「맹자『맹자』」(서울대 철학사상연구소, 2004) `etc/1_022.pdf`, 193쪽. 이미지는 선명하나 텍스트 층 인코딩이 깨져 OCR 필요. 본문은 줄글 해설이며 구절을 `(진심상9)` 형태로 인용. 공개 서비스 전 권리자 허락 확인
2. **2층(결정)**: 한문 『孟子』 전산 입력본 `etc/origin.hwp.pdf` (48쪽, 14편, 저본 阮元校刻 十三經注疏, 1998 李康齊 대교). 위치 코드 `MZ` + 편(2) + 장(2) + 절(2) + 문장(2). 해설서의 `진심상9` 같은 인용은 이 코드의 13편 9장에 대응. 한국어 질문 → 한문 검색이 필요하므로 다국어 임베딩이 필수 조건. 이 전산본의 이용 허락 확인 필요
- 이전의 Gutenberg 니체 샘플 안은 폐기
3. 임베딩 모델 최종 선택은 M1 비교 실험 결과로 결정

## 9. 지식 소스 층 (MVP 이후 확장, 설계만 반영)

| 층 | 내용 | 용도 |
|---|---|---|
| 1. 읽는 책 | 사용자가 읽는 번역본·해설서 (현재: 맹자 해설서 PDF, OCR 필요) | 근거 인용, 이해 확인 질문 (**MVP의 중심**) |
| 2. 원문·개념 | 한문 원문(장·절 코드로 1층과 연결, 현재 `origin.hwp.pdf`), 시대 배경, 용어집 | 원문 제시, 맥락 질문 (**MVP는 원문 조회까지**) |
| 3. 해설·비평 | 연구서, 백과 (영어 포함) | 다른 해석, 반론 |
| 4. 다른 철학자 | 대립·계승 관계 | 비교 질문 |
| 5. 현실 연결 | 직접 만든 사례 | 적용 질문 |

- 모든 청크에 `source_type`, `license`, `source_url` 메타데이터를 붙인다. MVP부터 필드는 둔다.
- 검색 정책: 본문 우선, "책 너머" 질문일 때만 2~5층을 추가 검색한다.
- 외부 해설 자료는 복제보다 출처 표시와 링크, 라이선스가 열린 자료를 우선한다.
- 스탠퍼드 철학백과(SEP): 이용 약관(2026-10-29 확인)상 비상업 목적의 읽기·복사·검색·링크만 허용, 전자 배포는 개인 기기·비공개 소그룹(30명 이하)·링크로 제한, 색인 목적 크롤링은 허용. 서비스에 내용을 넣어 제공하는 것은 허락 범위가 불명확하므로 **링크·출처 표시로 연결하거나 저자·Stanford 서면 허락을 받은 뒤에 사용**. 상업화(B2B) 시에는 특히 허락 필요.
- 청크 요약 색인(문단을 미리 요약해 검색에 쓰기)은 MVP 이후 M3에서 on/off 비교 실험으로 효과를 검증한다. 원문은 인용용으로 항상 보존.
