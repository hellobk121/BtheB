# BtheB M0 (인프라) Implementation Plan

> 참고: 구현 중 `app/llm`, `app/api`, `app/config.py`는 `app/engines/llm`, `app/features/chat`, `app/core/config.py`로 정리됐고, headless 호출에는 격리 옵션(`--safe-mode --strict-mcp-config`, 임시 cwd)이 추가됐습니다. 최종 구조는 README와 스펙 4절을 따릅니다.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 저장소 뼈대, LLM 어댑터(headless 구현), `/health`와 최소 `/chat`, README를 만들어 로컬에서 서버가 뜨고 "안녕" 한 번이 왕복되는 상태로 첫 push 직전까지 간다.

**Architecture:** FastAPI 백엔드가 `LLM` 인터페이스 하나만 알고, 구현체는 환경변수 `LLM_BACKEND`로 고른다. 지금은 `claude -p`를 호출하는 `ClaudeCliLLM`만 구현하고, `api`는 M5에서 추가한다. RAG(`rag/`)와 페르소나(`persona/`)는 빈 패키지로 자리만 둔다.

**Tech Stack:** Python (venv), FastAPI, uvicorn, pytest, httpx(TestClient 의존). 프론트(React)는 M2.

**Spec:** `docs/superpowers/specs/2026-10-29-btheb-design.md` (M0 = 6절)

## Review Focus

1. `POST /chat`에 빈 문자열 또는 공백만 있는 `message` → 422 (LLM 호출 없음)
2. `message`가 4000자 초과 → 422
3. `claude` 실행 파일이 없음 / 비정상 종료 / 시간 초과 → 502와 한 줄 오류 메시지 (스택트레이스 노출 금지)
4. `message`가 `-`나 `--`로 시작해도 CLI 옵션으로 해석되지 않음 (프롬프트는 stdin으로 전달)
5. `LLM_BACKEND`가 알 수 없는 값 → 서버 시작 시 명확한 오류. `.env`가 없어도 기본값 `cli`로 동작

### Task 2: LLM 어댑터

**Files:**
- Create: `backend/app/llm/base.py`, `backend/app/llm/claude_cli.py`, `backend/app/llm/factory.py`
- Test: `backend/tests/test_llm.py`

**Interfaces:**
- Produces:
  - `Message = TypedDict("Message", {"role": Literal["system","user","assistant"], "content": str})`
  - `class LLMError(Exception)`
  - `class LLM(Protocol): def generate(self, messages: list[Message]) -> str`
  - `class ClaudeCliLLM(runner=subprocess.run, timeout: int = 120)`, `.generate(...)`
  - `def get_llm(env: Mapping[str, str] = os.environ) -> LLM`

- [ ] **Step 1: 실패하는 테스트 작성** (`runner`를 가짜로 주입, 실제 CLI 호출 없음)
  - `test_generate_returns_stripped_stdout`: 가짜 runner가 stdout `"  답변\n"` 반환 → `generate([...])`가 `"답변"`
  - `test_prompt_goes_to_stdin_not_argv`: `messages`의 마지막 user가 `"--help"`일 때 runner에 전달된 `args`에 `"--help"` 없음, `input`에 포함
  - `test_system_and_history_are_in_prompt`: system/user/assistant 내용이 모두 `input`에 순서대로 포함
  - `test_nonzero_exit_raises_llmerror`, `test_timeout_raises_llmerror`(`subprocess.TimeoutExpired`), `test_missing_binary_raises_llmerror`(`FileNotFoundError`)
  - `test_factory_defaults_to_cli`: `get_llm({})` → `ClaudeCliLLM` 인스턴스
  - `test_factory_unknown_backend_raises`: `get_llm({"LLM_BACKEND": "x"})` → `ValueError`, 메시지에 `"x"` 포함
  - `test_factory_api_not_implemented`: `{"LLM_BACKEND": "api"}` → `NotImplementedError`(메시지에 "M5")
- [ ] **Step 2: 실행해서 실패 확인** — `cd backend && pytest tests/test_llm.py -v` Expected: FAIL (모듈 없음)
- [ ] **Step 3: `base.py` 구현** — 위 Produces 그대로
- [ ] **Step 4: `claude_cli.py` 구현** — `claude -p` 비대화형 호출, 프롬프트는 stdin(`input=`)으로 전달, `capture_output=True, text=True, encoding="utf-8"`. **구현 전에 `claude --help`로 실제 플래그를 확인하고, 도구 사용(파일·셸)이 꺼진 채팅 전용 호출이 되도록 옵션을 고른다.** 꺼지지 않으면 README에 한계로 기록. 프롬프트 조립은 역할 라벨(`System:`/`User:`/`Assistant:`) 텍스트
- [ ] **Step 5: `factory.py` 구현** — `LLM_BACKEND` 기본 `"cli"`, `CLAUDE_CLI_TIMEOUT` 읽기
- [ ] **Step 6: 테스트 통과 확인** — Expected: PASS (전부)
